Hostel Management System

Unified Residential Administration, Safety & Governance Platform
  • Residential Lifecycle: Automated tracking of all student activities from admission to checkout.
  • Role Governance: Tailored portals for Admin, Warden, Student, Parent, and Staff.
  • Poka-Yoke Error Proofing: Enforces zero double bed allocations and gate curfew locks.
  • FastAPI & MySQL Engine: Asynchronous backend delivering sub-10ms transactional execution speed.
  • Total Quality Management: Closed-loop Kaizen grievance handling and live activity logs.

Problem Statement & Quality Gaps

  • Manual Paper Logbooks: Cause unverified exits, roll-call queues, and zero curfew visibility.
  • Duplicate Bed Allocations: Absence of atomic locks leads to double-booking and capacity conflicts.
  • Zero Parent Visibility: Guardians lack remote access to verify daily attendance, gate passes, or dues.
  • Untracked Maintenance Delays: Facility tickets on loose paper get lost with no SLA tracking.
  • Mess Inventory Leakage: Pantry commodities suffer undocumented stock shrinkage without alerts.

Stakeholder Ecosystem & Access Control

  • Campus Administrator: Full institutional authority over users, hostel blocks, and audit logs.
  • Hostel Warden: Daily roll-call attendance, atomic bed allocations, and outpass approvals.
  • Student Resident: Bed assignment inspection, gate pass requests, and maintenance tickets.
  • Parent / Guardian: Remote ward telemetry showing live campus presence (Checked-In/Out) and dues.
  • Operational Staff: Gate station for pass verification and technician maintenance dispatch.

Total Quality Management (TQM)

  • Poka-Yoke (Mistake-Proofing): Database constraints enforce single-bed invariants and curfew locks.
  • Customer & Stakeholder Focus: Role-tailored dashboards eliminate clutter; 4 themes ensure usability.
  • Kaizen (Continuous Improvement): Closed-loop maintenance ticketing (Open → Resolved → Closed).
  • Technician Routing: Workorders dispatched by trade skill (Electrician, Plumber, Carpenter).
  • Process Control & Latency SLA: Sub-10ms query execution achieved via 25+ composite B-Tree indexes.

Software Requirements Specification

  • Individual Bed Hierarchy: Hostel → Block → Floor → Room → Bed Slot with capacity limits.
  • Formal Gate Pass Workflow: Automated pass request, warden approval, and exit/entry logging.
  • Digital Roll-Call Attendance: Daily student attendance recording with automated monthly percentages.
  • Sub-10ms Transactional SLA: High-concurrency async endpoints responding under 10ms target.
  • Data Security & ACID Integrity: JWT authentication, cryptographic hashing, and horizontal isolation.

High-Performance System Architecture

  • Tier 1 (Client Presentation): React 19 + TypeScript Single Page Application built with Vite.
  • Tier 2 (API Gateway & Security): FastAPI ASGI framework with 14 modular REST API controllers.
  • Tier 3 (Authentication & Interceptors): Cryptographic JWT bearer tokens and least-privilege RBAC guards.
  • Tier 4 (Business Logic & Poka-Yoke): Invariant validation engine preventing capacity breaches.
  • Tier 5 (Database Storage Engine): MySQL 8.0 relational database with SQLAlchemy ORM pooling.

Entity-Relationship (ER) Architecture

  • Third Normal Form (3NF): 23+ normalized relational tables eliminating redundancy and anomalies.
  • Physical Entities: rooms (capacity, type) and room_allocations (student_id, room_id, bed_number).
  • Curfew & Security: gate_passes (pass_number, departure_time, expected_return, is_late).
  • Facility Operations: issue_requests (category, priority, assigned_staff_id, target_deadline).
  • Poka-Yoke Constraints: Composite UNIQUE (room_id, bed_number, active) guarantees zero duplicate beds.

Core Operational Workflows & CRUD

  • Bed Allocation: Warden views visual Bed Grid → Auto slot selection → Atomic allocation → Vacate.
  • Gate Pass Curfew: Student requests pass → Warden approves → Guard logs exit → Auto late return flag.
  • Maintenance Workorder: Student files defect → Warden assigns technician & deadline → Resolved.
  • Daily Roll-Call: Warden marks daily attendance → Real-time monthly percentages and absentee lists.
  • Pantry Inventory: Warden updates stock levels → Minimum threshold triggers automated alerts.
